## Highlights

<Notice variant="warning" icon={<IconCiWarningFill />}>
  Highlights is experimental and subject to change. Try the [interactive
  playground](/highlights) before replacing Shiki in production.
</Notice>

Highlights is a small code highlighter with 67 hand-written language lexers in
WebAssembly. It has no grammar downloads and can produce HTML, Shiki-compatible
tokens, streamed tokens, or incrementally updated editor tokens.

Install Highlights from npm:

```sh
pnpm add @pierre/highlights
```

The package runs in Node.js, browsers, and Cloudflare Workers. Its conditional
exports select and initialize the matching WebAssembly loader automatically.

### HTML

`codeToHtml(input, options)` returns a self-contained `<pre class="highlights">`
fragment as a `Uint8Array`. `input` can be a `string`, `Uint8Array`, or
`ArrayBuffer`.

<DocsCodeExample {...highlightsHtml} />

The returned bytes are a zero-copy view of WebAssembly memory and remain valid
only until the next call on that highlighter. Send or decode them immediately,
or call `.slice()` before retaining them.

### Tokens

`codeToTokens()` accepts the same input types as `codeToHtml()` and returns one
`ThemedToken[]` per line, with absolute UTF-16 offsets. The result also includes
`fg`, `bg`, `themeName`, and `rootStyle` when the selected theme provides them.

<DocsCodeExample {...highlightsTokens} />

The shared token options are:

| Option                  | Behavior                                                                                            |
| ----------------------- | --------------------------------------------------------------------------------------------------- |
| `lang`                  | A built-in language name or alias                                                                   |
| `theme`                 | One Zed `Theme` or `ThemeFamily`                                                                    |
| `themes`                | Named themes such as `{ dark, light }`; emits per-theme CSS properties                              |
| `cssVariablePrefix`     | Prefix for multi-theme properties; defaults to `--hls-`                                             |
| `defaultColor`          | Theme key applied inline (`light` unless set); `false` emits every theme color as a custom property |
| `tokenizeMaxLineLength` | Collapses longer lines into one unthemed token for DOM safety                                       |

Choose either `theme` or `themes`. `codeToHtml()` accepts one `theme`, while the
tokenization APIs accept either form.

### Streaming

`StreamTokenizer` owns an isolated WebAssembly instance, preserves lexer state
between chunks, and tokenizes each completed chunk once. Token offsets stay
relative to the complete stream.

<DocsCodeExample {...highlightsStream} />

`pushCode(chunk)` accepts strings and returns only completed lines. `end()`
returns the remaining lines, including the empty final line after a trailing
terminator. Call `dispose()` when the stream is no longer needed; calling
`end()` also disposes it.

### Incremental editing

`LiveTokenizer` keeps the document, line table, token records, and per-line
lexer states in WebAssembly. Edits are batched UTF-16 range replacements. It
re-tokenizes from the first changed line until the outgoing lexer state matches
the pre-edit state.

<DocsCodeExample {...highlightsLive} />

Passing a half-open `renderRange: [startLine, endLine]` to the constructor,
`applyEdits()`, or `reset()` tokenizes synchronously up to `endLine`. Updated
lines inside the range are returned in `update.lines`; completed lines outside
it can arrive synchronously through `onDeferTokenize`, and the remaining work
runs in background slices. Without a range, updates converge synchronously and
`update.lines` is empty, so read changed lines with `lineChanges` and
`getLineTokens()`.

| Member                                          | Purpose                                                    |
| ----------------------------------------------- | ---------------------------------------------------------- |
| `revision`, `lineCount`, `pendingTokenization`  | Current document and deferred-work state                   |
| `applyEdits(edits, options?)`                   | Apply a validated edit batch                               |
| `reset(code, options?)`                         | Replace the complete document                              |
| `getLineLength()`, `getLineText()`, `getText()` | Read the exact document, preserving `LF`, `CRLF`, and `CR` |
| `getLineTokens()`                               | Read themed tokens and bracket-ignored ranges for one line |
| `getLineRecords()`                              | Read a zero-copy packed token-record view                  |
| `flush()`, `pause()`, `resume()`                | Control deferred tokenization                              |
| `dispose()`                                     | Release the isolated WebAssembly instance                  |

`getLineRecords()` views are invalidated by the next edit, reset, deferred
slice, or disposal. Copy `.data` when ownership is required. `tokenNames` maps
each packed token ID to its syntax-scope name.

`applyEdits()`, including a no-op batch, `reset()`, and `flush()` resume work
suspended by `pause()`.

### Themes

Highlights accepts Zed `Theme` and `ThemeFamily` objects, including three-,
four-, six-, and eight-digit hex colors. It bundles Pierre themes and themes
from Shiki's catalog. Import named themes from `@pierre/highlights/themes`, use
a per-theme default subpath such as `@pierre/highlights/themes/vitesse-dark`, or
lazy-load by ID through the `themes` map.

<DocsCodeExample {...highlightsThemes} />

`cssVariables` emits `var(--hls-*)` colors, while `toCSS(theme)` creates the
matching declarations from any Zed theme. CSS-variable mode controls colors
only; it ignores the theme's `font_style` and `font_weight` values. Sub-scopes
such as `keyword.control` inherit colors from their nearest configured parent.

### Diffs integration

Register the adapter once before creating or rendering Diffs content. Highlights
then powers files, file diffs, multi-file diffs, patch diffs, streams, React and
vanilla renderers, SSR preloads, and edit mode.

The adapter requires the optional `@pierre/highlights` peer dependency. Install
it in the application that imports `@pierre/diffs/highlights`.

<DocsCodeExample {...highlightsDiffs} />

`setHighlighter(highlightsHighlighter)` changes the process-wide Diffs
highlighter. New renderers use it immediately, and existing file or diff
renderers adopt it on their next render. Running streams and attached editors
keep the implementation they captured until they are recreated. Pass
`shikiHighlighter` back to `setHighlighter()` to restore the default.

Theme names resolve to bundled Highlights themes. Diffs loads bundled themes
automatically, so components, SSR preload helpers, and streams do not need a
separate `preloadHighlighter()` call. Use it only to warm themes before the
first client render or before calling synchronous low-level render APIs. Its
`langs` option has no effect with Highlights because languages are built in.
Call `registerHighlightsTheme(name, theme)` before rendering to add or replace a
name. Unknown names reject during loading. The theme's git and terminal colors
also control Diffs addition, deletion, and modified colors.

For example, warm both default themes before mounting your app:

<DocsCodeExample {...highlightsPreload} />

Highlights accepts aliases such as `shellscript`, `shellsession`, `git-commit`,
and `git-rebase` directly. The Diffs adapter also maps `ansi` to plain text and
`riscv` to assembly. Other unsupported languages render as plain text. Edit mode
uses `LiveTokenizer`. The Diffs worker pool remains Shiki-only and defers
initialization while a custom highlighter is selected.

### Server rendering

Pass `highlighter` to `preloadFile` to select Highlights for one server render.
This keeps concurrent renders independent of the global registration and loads
the requested themes before rendering.

client to use Highlights before hydrating that result.

#### `@pierre/highlights/themes`

The themes entry exports `cssVariables`, `toCSS()`, the lazy `themes` loader
map, and every bundled theme as a named `Theme`. Each theme is also available
from a per-theme default subpath such as
`@pierre/highlights/themes/vitesse-dark`.

#### `@pierre/diffs/highlights`

The Diffs adapter entry exports `highlightsHighlighter` as both its default and
named export. `registerHighlightsTheme(name, theme)` adds or replaces a theme
name before rendering.
