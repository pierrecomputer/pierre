# Highlights benchmarks

These benchmarks measure HTML generation, themed tokens, streaming, and live
editing. Shiki is the HTML/token baseline; `tree-sitter-highlight` also runs in
HTML mode. Live edits compare against a full Highlights token rebuild.

## Run

```sh
moon run highlights:bench
moon run highlights:bench-tokens
moon run highlights:bench-stream
moon run highlights:bench-live
```

- `bench`: HTML generation for CSS, HTML, JSONC, and TypeScript.
- `bench-tokens`: complete `codeToTokens` output on TypeScript.
- `bench-stream`: streaming tokenization in 4,096-character chunks.
- `bench-live`: initialization, edits, cached reads, and retained Wasm memory.

Pass `-- --wide` to the first three tasks to retain all table columns.

Source fixtures live in [`fixtures`](./fixtures); the scripts generate the
Unicode and 100k-line cases.

Recorded on **2026-09-14**, using Bun 1.4.0 on an Apple M4 Pro (14 cores, 48 GB
RAM, macOS arm64). The optimized Wasm build measured 151,073 bytes, or 67,538
bytes gzipped. These tables preserve one complete run of each mode, executed
sequentially; they are not regenerated by the build.

## Sampling

Both scripts use [`measure.ts`](./measure.ts): a 200 ms warmup and 1.5-second
sampling budget per case, at least 20 samples, and rotating contender order.
Shiki's line-length and time limits are disabled.

Throughput uses the median of per-call batch averages (~5 ms batches), in MiB/s.
Live editing measures individual calls and reports median and p95. Cleanup
counts toward the budget but is excluded from latency.
